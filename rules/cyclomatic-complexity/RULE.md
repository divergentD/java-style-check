# 函数实现的圈复杂度

## 规范与检查边界

- 检查范围内函数实现的平均圈复杂度不得大于 **5**，任何单个函数实现的圈复杂度不得大于 **20**。两项必须同时满足，等于上限时允许通过。
- 平均值采用算术平均：`average = Σ CC(f) / N`；最大值为 `maximum = max CC(f)`。比较时使用未四舍五入的平均值；展示的小数不改变判断。
- 统计所有可见性的手写方法、构造方法及有实现的接口 default/static/private 方法，生产代码和测试代码均适用。抽象方法、无方法体的接口声明、native 方法，以及 MapStruct、Lombok 等生成代码不计入。
- 先声明统计范围：默认使用本次检查的 Java 文件，用户指定全量扫描时使用指定目录或项目的全部适用函数。只检查 diff 时，应统计涉及函数的完整实现并标明“变更函数范围”，不得宣称项目平均值合格。不得引入范围外函数或新增无实际职责的方法稀释平均值。
- `N = 0` 时标记“不适用（检查范围内无函数实现）”，不得用平均值为零表示通过。

### 计数口径

优先使用项目已有的 Java AST 静态分析工具，记录工具版本、配置和统计范围。本规则默认采用 [Checkstyle CyclomaticComplexity 的决策点口径](https://checkstyle.org/checks/metrics/cyclomaticcomplexity.html)，`switchBlockAsSingleDecisionPoint = false`：

- 每个函数实现从 `1` 开始；`if`（包括 else if）、循环、三元表达式、catch、switch、非 default 的 case，以及短路运算符 `&&` / `||` 均增加决策点；支持的 case `when` 守卫也计入。
- `else`、`default`、`try`、`finally` 与无条件 return/throw 不单独增加决策点。嵌套深度本身不额外增加圈复杂度。
- 使用同一工具和配置汇总所有函数，不得通过删减计数 token 或改用 switch 整体计为一个决策点来规避阈值。lambda、局部/匿名类、初始化块和新语法的处理须明确工具口径；初始化块不混入函数平均值，嵌套方法不得重复计入外层函数。
- 不得用正则匹配关键字或操作符代替可靠计量；注释、字符串和没有可靠解析的代码不能据此判定通过。无法完成计量时明确说明原因及未完成范围。

单函数检查工具的 `max = 20` 只能验证最大值，平均值仍须汇总实际函数指标后验证。不得用“每个函数 ≤ 5”代替本规则的平均值要求。

## 正例

```java
/** 累加正数，null 输入返回零。 */
public static int sumPositive(int[] values) {
    if (values == null) {
        return 0;
    }
    int sum = 0;
    for (int value : values) {
        if (value > 0) {
            sum += value;
        }
    }
    return sum;
}
```

函数复杂度为 `1 + if + for + if = 4`。检查范围仅含该函数时，平均值为 4，最大值为 4，两项均合格。

## 反例

```java
/** 按顺序修订积分。 */
public static int adjust(int score) {
    if (score < 0) {
        score = 0;
    }
    if (score > 100) {
        score = 100;
    }
    if (score == 50) {
        score++;
    }
    if (score % 2 == 0) {
        score += 2;
    }
    if (score % 5 == 0) {
        score += 5;
    }
    return score;
}
```

函数复杂度为 `1 + 5 个 if = 6`。检查范围仅含该函数时，平均值为 6，违反平均值上限；最大值为 6，符合单函数上限。若它属于更大检查范围，须重新汇总，不能仅因其超过 5 就认定违规。

### 边界与最大值反例

| 检查范围内的函数复杂度 | 平均值 | 最大值 | 结论 |
| --- | --- | --- | --- |
| 2、4、9 | 5 | 9 | 合格，平均值等于上限，且允许单函数超过 5 |
| 4、6、6 | 16/3，约 5.33 | 6 | 平均值超标 |
| 5 个复杂度为 1 的函数，另 1 个为 20 | 25/6，约 4.17 | 20 | 合格，最大值等于上限 |
| 20 个复杂度为 1 的函数，另 1 个为 21 | 41/21，约 1.95 | 21 | 单函数最大值超标，平均值合格也不能通过 |

## 检查报告与修复

- 报告规则 ID `cyclomatic-complexity`、统计范围、工具/配置、函数数 N、平均值、最大值，以及两项是否合格。单函数超标列出文件、行号、函数签名和 CC；平均值超标列出主要复杂函数及职责拆分建议。
- 修复时按实际职责提取方法或简化分支，并复查整体平均值与最大值。提前返回未必降低圈复杂度，应以重新计量为准。
- 保留判断顺序、空值与异常行为、副作用、权限及事务/状态边界；不得删除业务分支、隐藏函数或增加无职责方法来降低指标。涉及业务行为的重构按项目要求执行相关测试。
